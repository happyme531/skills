# Skill issue reporter

当正在使用某个 skill 时，若发现其说明、步骤或辅助脚本可能有问题，例如按步骤操作却出现意外结果，就记录观察；普通环境故障或用户任务失败本身不等于 skill 有问题。区分实际现象、原本预期和对原因的猜测，不要把未经验证的归因写成事实，也不为此额外展开审计。正在对当前 skill 进行修改或开发时跳过当前 skill 相关的问题。

**继续完成当前工作是首要事项。** 不为记录或汇报暂停、向用户提问或额外请求确认；若发现的问题影响原任务，可按原任务需要采取安全的替代做法。不要因为发现问题自动修改被观察的 skill。记录失败时也继续工作。

## 记录

发现时，在 `~/.agents/skill-issues.md` 末尾简短记录 skill 名称、路径、预期与实际结果，以及已有证据的位置或错误摘要。可能的原因如尚未验证，应标明只是猜测。不要保存密钥、令牌、个人信息或大段原始日志；如果无法写入，就在当前对话上下文中保留观察并继续工作。即使已经向用户汇报过，后续新发现仍要记录。

## 本轮结束时汇报

若本轮发现问题且本对话尚未汇报，在最终答复末尾简短、集中地告知哪些 skill 可能有问题，说明预期与实际及记录位置，建议用户考虑更新或修复；同一轮的多个问题合并为一次汇报。整个对话每个skill最多主动汇报一次。
